================================================================================
  GUIA DE DEMOSTRACION PARA EL PROFESOR
================================================================================

REQUISITO: "Es posible desplegar tantas instancias del mismo módulo como se
requiera en distintas máquinas o en la misma a criterio del profesor."

Este sistema CUMPLE completamente con el requisito y permite:
  - Añadir instancias dinámicamente en cualquier momento
  - Detener instancias súbitamente (simulando crash)
  - Desplegar en la misma máquina o en máquinas diferentes
  - Escalar sin límite de instancias

================================================================================

ARQUITECTURA DEL SISTEMA
-------------------------

MODULOS INDEPENDIENTES:
  1. EV_Central (PC_A) - Central de gestión
  2. EV_CP_Engine (PC_B) - Motor del Charging Point
  3. EV_CP_Monitor (PC_B) - Monitor del Charging Point  
  4. EV_Driver (PC_B) - Simulador de conductor
  5. Dashboard Web (PC_A) - Interfaz visual

CARACTERISTICAS:
  - Cada módulo es INDEPENDIENTE (contenedor Docker)
  - Comunicación mediante Kafka (desacoplada)
  - Sistema de colas automático para múltiples drivers
  - Reconexión automática en caso de caída
  - Sin límite en el número de instancias

================================================================================

CASO 1: DESPLEGAR MULTIPLES INSTANCIAS INICIALES
-------------------------------------------------

PASO 1: Lanzar CPs iniciales

  > Opción [1] - Múltiples CPs
  > Número de CPs: 3

RESULTADO:
  - Se crean DRIVER_001, DRIVER_002, ..., DRIVER_005

  - Sistema de colas automático si varios van al mismo CP

  - Dashboard web: http://localhost:8080

CASO 3: SIMULAR CRASH SUBITO DE UN MODULO
------------------------------------------

DEMOSTRACION: Simular fallo de un CP
-------------------------------------

El profesor pide: "Simula el crash súbito del CP_002"

OPCION 1: Desde PowerShell
  docker stop engine_CP_002 monitor_CP_002

OPCION 2: Cerrar las terminales con Ctrl+C

OPCION 3: Simular crash más realista
  docker kill engine_CP_002 monitor_CP_002

COMPORTAMIENTO DEL SISTEMA:
  1. El CP_002 desaparece inmediatamente
  2. La Central detecta la pérdida de conexión
  3. El CP_002 se marca como DESCONECTADO en dashboard
  4. Si había un driver cargando:
     - La sesión se interrumpe
     - El driver recibe error
  5. Los demás CPs siguen funcionando normalmente

VERIFICACION:
  - Dashboard web: CP_002 aparece como DESCONECTADO o desaparece
  - Los demás CPs (CP_001, CP_003, CP_004, CP_005) siguen ACTIVOS

RECUPERACION:
  Para "recuperar" el CP_002 caído:
  > PC_B_RUN.bat
  > Opción [1]
  > Número: 1
  
  Se creará CP_006 (el sistema detecta que CP_002 ya no existe)

CASO 4: DESPLEGAR EN MAQUINAS DIFERENTES
-----------------------------------------

CONFIGURACION:

PC_A (Servidor Central):
  1. Ejecutar: PC_A_RUN.bat
  2. Anotar IP detectada (ej: 192.168.1.43)
  3. Servicios corriendo:
     - Kafka (puerto 9092)
     - MySQL (puerto 3306)
     - EV_Central (puerto 5000)
     - Dashboard Web (puerto 8080)

PC_B (Estación de CPs y Drivers):
  1. Copiar archivo central_ip.txt desde PC_A
  2. Ejecutar: PC_B_RUN.bat
  3. Lanzar CPs y Drivers

PC_C (Otra estación):
  1. Copiar archivo central_ip.txt desde PC_A
  2. Ejecutar: PC_B_RUN.bat
  3. Lanzar más CPs y Drivers

RESULTADO:
  - Todos los CPs de todas las máquinas se registran en la Central
  - Todos aparecen en el mismo dashboard web
  - El sistema funciona de forma distribuida

VERIFICACION:
  - Desde PC_A: http://localhost:8080
  - Desde PC_B: http://192.168.1.43:8080
  - Ver todos los CPs de todas las máquinas

COMANDOS UTILES PARA DEMOSTRAR AL PROFESOR
-------------------------------------------

Ver TODOS los contenedores del sistema:
  docker ps --filter "label=project=evcharging-pc-b"

Ver solo CPs:
  docker ps --filter "label=component=engine"

Ver solo Drivers:
  docker ps --filter "label=component=driver"

Ver cuántos de cada tipo hay:
  docker ps --filter "label=component=engine" --format "{{.Names}}" | wc -l
  docker ps --filter "label=component=driver" --format "{{.Names}}" | wc -l

Detener UN módulo específico (simular crash):
  docker stop engine_CP_003

Detener TODOS los drivers (reset):
  docker stop $(docker ps -q --filter "label=component=driver")

Detener TODOS los CPs (reset):
  docker stop $(docker ps -q --filter "label=component=engine")

Detener TODO el sistema PC_B:
  PC_B_STOP_ALL.bat

Ver logs de un módulo específico:
  docker logs engine_CP_001
  docker logs driver_DRIVER_003

PUNTOS CLAVE PARA LA DEMOSTRACION
----------------------------------

1. MODULARIDAD:
   - Cada componente es independiente (contenedor Docker)
   - Se pueden lanzar/detener individualmente
   - No afecta al resto del sistema

2. ESCALABILIDAD:
   - Se pueden añadir instancias en cualquier momento
   - El sistema detecta automáticamente las existentes
   - Nombres secuenciales automáticos

3. TOLERANCIA A FALLOS:
   - Si un CP cae, los demás siguen funcionando
   - La Central detecta desconexiones
   - Sistema de colas maneja interrupciones

4. DISTRIBUCION:
   - Puede ejecutarse en la misma máquina o en varias
   - Comunicación mediante Kafka (desacoplada)
   - Central único, múltiples estaciones

5. AUTOMATIZACION:
   - No requiere editar configuraciones manualmente
   - Scripts detectan estado actual del sistema
   - IDs y puertos asignados automáticamente
