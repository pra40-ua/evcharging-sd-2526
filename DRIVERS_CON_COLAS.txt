================================================================================
  SISTEMA DE MULTIPLES DRIVERS CON COLAS
================================================================================

IMPLEMENTADO: Sistema de colas para gestionar múltiples drivers que solicitan
el mismo Charging Point.

================================================================================

QUE SE HA HECHO
---------------

1. MODIFICADO: EV_Central.py
   - Añadida estructura de colas por CP (CP_COLA_ESPERA)
   - Cuando un driver solicita un CP ocupado, se añade a la cola
   - Cuando un CP termina una sesion, procesa automaticamente el siguiente
     driver en cola

2. MODIFICADO: EV_Driver.py
   - Añadido manejo del evento "EN_COLA"
   - Muestra posicion en cola cuando el CP esta ocupado
   - Espera turno automaticamente

3. CREADO: PC_B_RUN_MULTIPLE_DRIVERS.bat
   - Pregunta cuantos drivers lanzar (1-5)
   - Pregunta cuantos CPs estan disponibles
   - Asigna drivers aleatoriamente a los CPs
   - Cada driver en su propia terminal

4. ACTUALIZADO: PC_B_RUN.bat
   - Nuevo menu con 3 opciones:
     [1] Multiples CPs
     [2] Multiples Drivers
     [3] Clasico (1 CP + 1 Driver)

================================================================================

COMO FUNCIONA EL SISTEMA DE COLAS
----------------------------------

ESCENARIO 1: CP DISPONIBLE
  Driver 1 solicita CP_001
  -> CP_001 esta libre
  -> Driver 1 autorizado inmediatamente
  -> Carga comienza

ESCENARIO 2: CP OCUPADO
  Driver 1 solicita CP_001 -> Autorizado (cargando)
  Driver 2 solicita CP_001 -> En cola (posicion 1)
  Driver 3 solicita CP_001 -> En cola (posicion 2)
  
  Cuando Driver 1 termina:
    -> Driver 2 autorizado automaticamente
    -> Driver 3 avanza a posicion 1

ESCENARIO 3: MULTIPLES DRIVERS, MULTIPLES CPs
  5 Drivers, 3 CPs disponibles
  - Asignacion aleatoria
  - Algunos drivers pueden ir al mismo CP
  - Se forman colas automaticamente
  - Procesamiento automatico cuando se libera un CP

================================================================================

COMO USAR
---------

PASO 1: Lanzar CPs
  > PC_B_RUN.bat
  > Opcion [1]
  > Ingresar numero de CPs (ej: 3)

PASO 2: Lanzar Drivers
  > PC_B_RUN.bat (en otra terminal)
  > Opcion [2]
  > Ingresar numero de Drivers (ej: 5)
  > Ingresar numero de CPs disponibles (ej: 3)

RESULTADO:
  - 5 terminales de Drivers se abren
  - Cada uno solicita un CP aleatorio
  - Algunos pueden ir al mismo CP
  - Los que encuentren CP ocupado entran en cola
  - Procesamiento automatico cuando hay liberacion

================================================================================

FLUJO COMPLETO
--------------

1. Driver envia solicitud a Central via Kafka
2. Central verifica estado del CP solicitado:
   
   SI CP LIBRE:
     -> Autoriza al driver inmediatamente
     -> Driver recibe "AUTORIZADO"
     -> Sesion comienza
   
   SI CP OCUPADO:
     -> Añade driver a cola del CP
     -> Driver recibe "EN_COLA" con posicion
     -> Driver espera
     -> Cuando CP se libera:
        -> Central autoriza automaticamente al siguiente en cola
        -> Driver recibe "AUTORIZADO"
        -> Sesion comienza

3. Driver recibe ticket cuando termina
4. Driver se detiene automaticamente

VENTAJAS DEL SISTEMA
--------------------

1. AUTOMATICO: No requiere intervencion manual
2. JUSTO: Orden de llegada (FIFO - First In First Out)
3. EFICIENTE: Procesamiento inmediato cuando se libera un CP
4. ESCALABLE: Maneja multiples colas simultaneamente
5. TRANSPARENTE: Los drivers ven su posicion en cola

================================================================================

PRUEBAS RECOMENDADAS
--------------------

Prueba 1: Un CP, Multiples Drivers
  - Lanzar 1 CP
  - Lanzar 5 Drivers al mismo CP
  - Verificar que forman cola
  - Verificar procesamiento secuencial

Prueba 2: Multiples CPs, Mas Drivers
  - Lanzar 3 CPs
  - Lanzar 8 Drivers (asignacion aleatoria)
  - Verificar colas en algunos CPs
  - Verificar que otros CPs procesan directamente

Prueba 3: Saturacion y Liberacion
  - Lanzar 2 CPs
  - Lanzar 10 Drivers
  - Observar formacion de colas largas
  - Observar procesamiento progresivo

================================================================================

GESTION DE CONTENEDORES
------------------------

Todos los drivers tienen labels de Docker:
  - project=evcharging-pc-b
  - component=driver
  - driver_id=DRIVER_001, DRIVER_002, etc.

Para detener todos los drivers:
  > PC_B_STOP_ALL.bat

Para listar drivers activos:
  > docker ps --filter "label=component=driver"

Para ver solo CPs:
  > docker ps --filter "label=component=engine"

================================================================================

COMANDOS UTILES
---------------

Ver todos los contenedores de PC_B:
  docker ps --filter "label=project=evcharging-pc-b"

Ver solo drivers:
  docker ps --filter "label=component=driver"

Detener todos los drivers:
  docker stop $(docker ps -q --filter "label=component=driver")

Ver logs de un driver especifico:
  docker logs driver_DRIVER_001

================================================================================

NOTAS IMPORTANTES
-----------------

1. Los drivers se detienen AUTOMATICAMENTE al recibir su ticket
2. NO es necesario detenerlos manualmente
3. Las colas se gestionan AUTOMATICAMENTE por la Central
4. Los drivers NO necesitan saber si hay cola, solo esperan
5. El orden es FIFO estricto por CP

================================================================================

COMPATIBILIDAD
--------------

Sistema compatible con:
  - Modo clasico (1 CP + 1 Driver)
  - Multiples CPs sin drivers
  - Multiples Drivers sin CPs extra
  - Sistema completo (multiples CPs + multiples Drivers)

No afecta:
  - Dashboard web
  - Telemetria
  - Base de datos
  - Sistema de tickets
